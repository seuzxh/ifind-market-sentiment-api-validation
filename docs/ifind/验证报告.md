## 2. 关键发现

### 2.1 当前阻塞已经与旧任务不同

当前本机能收到HTTP响应，无需继续套用旧云端“网络审批取消/代理失败”的结论。已验证的阻塞是当前三个环境变量作用域没有指定令牌。旧任务截图中的设置脚本内容不能证明凭证进入本次Windows进程。

### 2.2 CPS存在端点版本差异

附件给`history_data`的CPS=1标后复权；公开手册给`cmd_history_quotation`的CPS=1标不复权、CPS=3标后复权，且后者请求体为顶层JSON。当前证据不足以判定哪种语义适用于新端点，必须分开记录，不能混用。[官方历史行情手册](https://quantapi.51ifind.com/gwstatic/static/ds_web/quantapi-web/help-center/manual.html#历史行情-ths-hq)

### 2.3 MCP可作交叉核对，但不适合未经处理直接入库

- 对883957的首次查询额外返回700001，已从正式目录排除；按代码过滤而非取首行。
- 部分批次列顺序不同，已按表头抽取，不按列号定位。
- `883957.TI`返回“同花顺全A(沪深京)”，`883927.TI`返回“高股息股”；名称差异已保留。
- 所有单日价格列标注“元”。这不是指数点位单位的有效确认，已保留原标签并标未知。
- 两日结果表内日期明确，但参数元数据为“最新”，且返回倒序。报告使用表内日期做算术核对，同时保留日期冲突标记；不把该结果标为完整时间契约通过。

### 2.4 数值核对

2026-09-04主基准收盘1881.545，与历史对话成功样例的收盘一致；MCP涨跌幅-0.2964%，历史描述为-0.29643%，与显示精度差异相容。这只是数值一致性，不证明两通道复权或时间语义相同。

MCP两日检查：`abs(close-prev_close-chg)`均小于1e-9；`abs((close/prev_close-1)*100-pct)`均小于0.00005个百分点（按MCP四位小数四舍五入容差）。证据保存实际误差值。没有OHLC、量额或换手率的新验证结论。

## 5. 证据与可复核性

| 文件 | 性质 |
|---|---|
| ENV-01.json | 本机三个环境变量作用域的布尔检查，不含值 |
| NET-01/NET-02.json | 无鉴权请求体、UTC偏移时间、HTTP状态和供应商响应正文 |
| MCP-01～MCP-06.json | 工具返回的完整内容、请求问句和UTC获取时间；不是底层HTTP抓包 |

| manifest.json | 来源附件及本轮证据文件SHA-256；哈希证明文件一致性，不证明业务正确 |
| retest-*目录 | 复验脚本每次运行新建的请求/响应/预检；本轮仅真实无令牌预检及标记过的模拟检查 |
| delivery-checks.json | 文件、JSON/CSV、哈希、文档链接、脚本语法与目录覆盖检查 |

模拟预检目录`retest-20260909-092229-537-aea90289`明确标记为测试夹具，不是本机环境证据。真实环境证据以ENV-01和本轮另行运行的预检为准。没有将历史对话中“调用成功”的描述伪装成本轮原始响应。

## 6. 凭证就绪后的复验入口

需要PowerShell 7.2或以上。令牌由启动环境或当前用户变量提供，不写在命令参数中。

```powershell
# 在此目录运行，仅检查凭证可见性，不发业务请求
& '.\复验.ps1' -PreflightOnly

# 默认：2026-09-08单指数日线 + 用户给定交易日历区间
& '.\复验.ps1'

# 最小请求成功并确认结构后，再执行批量
& '.\复验.ps1' -TestId history_18_single,history_18_multi

# 单独记录CPS与重取结果
& '.\复验.ps1' -TestId history_single,history_cps_default,history_cps_1,history_cps_2,history_repeat
```

用例固定为2026-09-08，便于避开本轮早间尚未形成的09-09日线；MCP历史对照日另选09-04以复核旧样例。两者不应混合比较。脚本不会自动验收字段和语义，也不穷举未知参数；未来边界日2026-09-10在之后复验时须更新。详情见[待检查清单.md](待检查清单.md)。
