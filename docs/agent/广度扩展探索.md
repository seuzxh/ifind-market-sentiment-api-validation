# 广度扩展探索：预设方案与结果

日期：2026-09-09。继续复用409日候选沪深广度及主基准行情，只使用标准库，不新增依赖和接口调用。默认规则保持不变；以下方案在计算本轮结果前确定。

## 固定候选

上涨占比记为U，分母包括上涨、平盘、下跌。固定考察7个条件，不搜索阈值：

| 条件 | 定义 |
|---|---|
| 单日改善 | U高于前一交易日 |
| 连续改善 | U连续3次上升，需要连续4个交易日 |
| 正背离 | 主基准当日下跌，但U大于50% |
| 负背离 | 主基准当日上涨，但U小于50% |
| 极端普跌 | U不高于20% |
| 极端普涨 | U不低于80% |
| 普跌后修复 | 昨日U不高于20%，今日U高于昨日 |

每个条件分别观察独立触发、叠加原保守门禁（偏强且非Risk-Off）两个视角，共14个视角。统一检验条件下的次日上涨率；负背离与极端普涨也不预设次日必须下跌，不生成做空指令。

滞后广度按主基准实际日期寻找，禁止跳过缺失日；连续改善要求整个4日窗口同段且均有有效广度。每个条件与自己的可评估日期基准比较，报告不可评估数量。

## 选择与验证

沿用每段原样本的`max(40, floor(n×70%))`留出起点，不因广度缺失改变日期。只用开发期独立事件数至少20且覆盖率至少10%的候选，按命中率选择一个；平手按上表顺序，无合格候选则不选择。留出结果不得用于重选。

同时记录事件数、覆盖率、次日平均收益、最差收益和段内假设做多回撤，避免只看小样本高命中率。条件命中率不等于每日预测准确率，也不等于校准后的实时概率。

## 实际结果

A段开发期按预设门槛选出“单日改善”（86/178次，命中率63.95%），但在留出期只有47/94次，命中率48.94%，低于同一留出日期的基准53.19%，次日平均收益为-0.008%。因此不采用。

其他线索也没有形成稳定证据：连续改善开发期只有4次、留出期0%；普跌后修复留出期9次、上涨率66.67%，但次日平均收益为-0.145%，且最差收益-5.15%；负背离开发期21次、上涨率33.33%，留出期8次、上涨率87.50%，前后方向相反；极端普涨留出期8次、上涨率37.50%。

B段只有54个有效观察，开发期不足以选择候选；留出期各条件最多8次，不能据此选入规则。所有7个条件均保持`deployment_allowed=false`，默认规则不变。

机器结果见[扩展探索结果](breadth-explore-v1-results.json)，包含每段开发/留出数据、同组基准、覆盖率、最差收益、段内回撤、被排除日期和输入SHA-256。复现同[广度确认实验](广度确认实验.md)的输入文件，并加`--explore`参数。
