# 终端市场状态 Agent 设计规格

日期：2026-09-09

状态：待用户审阅

范围版本：第一阶段仅实现“日频市场状态识别 + 风格/情绪指数分析”。概念归因、T+1 预测模型和分钟盘中策略保留在后续阶段。

## 1. 目标与边界

该 Agent 通过终端提供两类查询：

- `status`：回答指定交易日或最新可用交易日的市场状态、风格强弱和主要依据。
- `forecast`：基于已经获取的日频数据，用固定规则给出下一交易日的方向倾向和风险模式。

“未来判断”只输出规则型结论，例如偏强、震荡、偏弱、Risk-On、Risk-Off，并列出触发规则的指标。第一阶段不训练模型、不输出概率、不承诺收益，也不自动下单。

本阶段使用纯 A 股沪深京范围。指数主基准为 `883957.TI`；核心风格配对为：

- SIZE：`700050.TI` 微盘 − `700047.TI` 大盘股；
- RISK：`700035.TI` 激进投资 − `700034.TI` 保守投资；
- MOM：`700038.TI` 高动量 − `700039.TI` 低动量。

补充观察指数包括高估值、低估值、高盈利、低盈利、五档规模、高股息和三个昨日情绪指数。补充指数只用于观察，不自动进入总评分。

2026-05-25 是全局分析边界。第一段截至 2026-05-22，第二段从 2026-05-26 开始；边界日和所有跨边界的收益、窗口、趋势、Spread、相关性与回溯均剔除。窗口不足时输出数据不足标记，不跨段补齐。

## 2. 方案选择

### 采用方案：Python 单文件 CLI

只使用 Python 标准库：`argparse`、`urllib.request`、`json`、`datetime`、`pathlib` 和 `hashlib`。不新增运行时依赖，不引入 Web 框架、数据库或任务调度服务。

预计文件：

```text
market_agent.py       # CLI、请求、校验、规则和输出
README.md              # 安装、配置和命令示例
docs/agent/规则说明.md # 指标公式、阈值、边界和已知限制
```

如果单文件明显超过可维护范围，再按职责拆分；在此之前不预先创建包层级、接口抽象或插件机制。

### 方案二：CLI + SQLite（记录，不在第一阶段实现）

使用 Python 标准库 `sqlite3` 保存原始响应索引、规范化日线、规则输出和版本信息。它适合需要重复查询、历史比较、离线回溯和增量更新的场景。代价是增加表结构、迁移、并发写入、备份和数据修复责任。只有当 JSON 文件查询速度、去重、历史检索或审计需求成为实际瓶颈时启用。

### 方案三：计算服务 + Web/API（记录，不在第一阶段实现）

将取数和规则计算放到独立服务，Pages 或其他前端只读展示结果。它适合多人访问、自动刷新、权限管理和后续交互式图表。代价是服务部署、密钥管理、API 认证、任务队列、监控和前后端维护。只有在需要共享实时结果或多人使用时启用；GitHub Pages 本身不保存令牌，也不直接调用 iFinD。

## 3. 用户界面与输出

命令：

```text
python market_agent.py status
python market_agent.py status --date 2026-09-08
python market_agent.py forecast
python market_agent.py forecast --date 2026-09-08
```

默认日期取当前环境日期；如果当天没有成熟的收盘数据，使用接口明确返回的最新交易日，并在输出中显示实际数据日期。指定日期不是交易日或未来日期时，不静默替换，返回可读的边界状态。

文本输出至少包含：

1. 数据日期、获取时间、接口状态和质量标记；
2. 主基准收益、5/20/60 日趋势（窗口不足则标记）；
3. SIZE、RISK、MOM 的当日 Spread 及方向；
4. 纯 A 股上涨、平盘、下跌和净广度（若 `p00112` 范围未确认，则标记有限可用）；
5. 高股息、昨日连板、昨日首板、昨日涨停的观察值；
6. `forecast` 的规则结论、触发依据、未满足的条件和禁止跨段提示。

可选的 `--json` 输出机器可读结果。JSON 顶层保存 `as_of_date`、`fetched_at`、`segment_id`、`quality_status`、`rules_version`、`source_versions` 和 `features`。原始响应另存本地，不嵌入终端摘要。

## 4. 数据流与接口

```text
命令行参数
  -> 读取 IFIND_ACCESS_TOKEN
  -> history_data：主基准、核心风格和补充指数日线
  -> data_pool/p00112：纯A广度（范围未确认时保留限制）
  -> real_time_quotation：仅 status 的盘中快照，可选
  -> 响应校验与标准化
  -> 交易日和分段边界检查
  -> 规则计算
  -> 文本或 JSON 输出
```

首版只依赖已成功验证的日频端点。`get_trade_dates` 用于交易日对齐；`basic_data_service` 用于代码和规则元数据；`smart_stock_picking`、`p03473`、`high_frequency` 不进入首版状态计算。`high_frequency` 当前只证明当日分钟数据可用，历史分钟回放不纳入本阶段。

所有请求必须保留端点、请求体摘要、参数版本、数据日期、响应哈希和获取时间。令牌只从环境变量读取，禁止写入文件、标准输出和异常消息。

## 5. 指标与规则

价格收益使用接口的 `pre_close` 和 `close`：

```text
r_t = close / pre_close - 1
RetN = close_t / close_(t-N) - 1
Spread = r_positive - r_negative
```

首版规则只使用可解释的少量信号：

- 市场方向：主基准当日收益正负与 Ret5/Ret20 方向一致时，增加对应方向分数；方向冲突时输出震荡候选。
- 风格偏好：SIZE、RISK、MOM 的 Spread 同向为风格共振；至少两组同向才形成偏好提示。
- 广度健康度：上涨比例高且净广度为正时，支持普涨；指数上涨但广度走弱时，标记权重托举风险。
- 情绪观察：昨日类指数与主基准同向，只作辅助证据，不把三类指数当作三次独立投票。
- 最终分类：规则输出“偏强 / 震荡 / 偏弱”与“Risk-On / 中性 / Risk-Off”两组标签，并列出触发项。

具体阈值集中写在 `docs/agent/规则说明.md`，采用固定版本号。第一版宁可输出“信号不足”，不通过隐式默认值补足缺失字段。

## 6. 异常、分段和数据质量

- HTTP 非 200、业务错误码非0、响应缺少目标代码或日期数组不等长：本次命令失败并输出原因。
- 非交易日：输出“无行情”，不补前一交易日。
- 未来日期：若接口返回占位行或部分字段为空，标记未来数据，不纳入状态和预测。
- `null`、缺字段、空数组和业务不适用字段分别保留，不能转成0。
- 2026-05-25 的三个昨日指数跳变只记录质量事件；相关日期和跨边界数据从计算输入剔除。
- 对任何指标先检查 `segment_id` 一致性。不同分段禁止参与同一窗口或 Spread。
- `vwap` 按用户确认记录为均价，但其单位和指数计算对象仍保留质量备注；首版不使用它决定状态。

## 7. 本地数据与回溯

默认将每次请求的脱敏响应、请求哈希、响应哈希和标准化结果保存到 `data/` 下按日期分目录的 JSON 文件；若用户只想查看结果，可通过 `--no-save` 关闭本地保存。保存目录不提交到 Git，令牌和原始敏感凭证永不落盘。

每条结果包含：`request_id`、`endpoint`、`as_of_date`、`fetched_at`、`segment_id`、`rules_version`、`quality_status` 和 `revision`。同日重取生成新 revision，不覆盖旧结果。

## 8. 错误处理和安全

令牌缺失时在发起网络请求前退出。网络超时、401、-1302、-1303 和其他业务错误均显示脱敏错误类别，不显示认证头。固定访问 `https://quantapi.51ifind.com/api/v1/`，禁止自动重定向。

CLI 不具备交易执行能力，不保存账户信息，不发送买卖指令。用户应自行管理令牌轮换；仓库和 GitHub Pages 只发布不含令牌的文档与静态结果。

## 9. 验证和验收

最小自检使用标准库 `assert`，覆盖：

1. `close/pre_close/chg/pct_chg` 恒等关系和零昨收；
2. 18条指数代码过滤、缺失和数组对齐；
3. 非交易日、未来日期和2026-05-25分段边界；
4. 缺失字段不被转换成零；
5. 规则在同一分段内计算，跨段输入被拒绝；
6. 令牌缺失时不发送请求。

验收标准：用户可以用一条命令获取可追溯的市场状态和规则型未来判断；输出显示实际数据日期、依据和质量状态；异常数据不会进入跨边界分析；复验命令可在不改代码的情况下重放固定日期；文档说明与实现保持一致。

## 10. 明确跳过的内容

第一阶段跳过 SQLite、Web/API 服务、前端图表、自动调度、概念归因、历史成分还原、T+1 概率模型、分钟历史回放和自动交易。触发条件分别是历史检索成为瓶颈、需要多人访问、概念数据契约通过、积累足够样本、供应商开放历史分钟回放或明确产生交易执行需求。
